# Reduce PDF Size 网站产品与实施方案

## 1. 项目目标

围绕英文关键词 `reduce pdf size` 建设一个真正可用的 PDF 压缩工具网站。用户可以在浏览器中选择 PDF、设置压缩强度、完成压缩并下载更小的文件。

首版的主要目标：

- 解决用户减小 PDF 文件体积的实际需求。
- 核心操作无需注册、无需付费。
- PDF 内容只在用户浏览器中处理，不上传服务器。
- 页面以英文搜索用户为主要受众。
- 工具体验优先，同时提供足够完整、真实、有帮助的 SEO 内容。
- 网站代码按 AGPL-3.0 要求公开对应源码。

## 3. 信息架构

首版包含以下页面：

- `/`：压缩工具、使用说明、质量说明、扫描件说明和 FAQ。
- `/privacy`：说明文件不上传、处理过程和浏览器内存清理方式。
- `/terms`：使用条款、结果免责和不支持的文件类型。
- `/source`：源码获取方式、AGPL 说明和第三方软件声明。

首页首屏必须直接呈现压缩工具，不能先用大段营销文案或图片阻挡用户操作。

## 4. 核心用户流程

1. 用户拖入 PDF，或通过文件选择器选择 PDF。
2. 网站验证文件类型、PDF 文件头和 100MB 限制。
3. 网站展示文件名和原始体积。
4. 用户选择压缩档位；默认使用 Balanced。
5. 用户点击 `Reduce PDF Size`。
6. 浏览器按需加载压缩引擎，并在独立 Web Worker 中处理。
7. 页面展示真实的处理阶段，不伪造精确百分比。
8. 成功后展示原始体积、输出体积、节省体积和压缩比例。
9. 用户下载 `{original-name}-reduced.pdf`，或重置后处理其他文件。

如果生成文件不小于原文件，必须丢弃生成结果并提示该 PDF 可能已经优化，建议尝试更强的压缩档位。不能显示负数节省比例，也不能把更大的文件宣传为压缩成功。

## 5. 压缩实现

### 5.1 引擎

- 使用 Ghostscript `pdfwrite` 的浏览器 WebAssembly 构建。
- 不直接发布多年未更新的旧预编译二进制；应基于实施时的当前稳定 Ghostscript 源码构建、固定版本并记录校验信息。
- WASM、Worker 和运行资源全部由本站同源托管，不依赖第三方 CDN。
- WASM 只在用户开始压缩后加载，避免影响首页首屏性能。

Ghostscript 官方压缩参数说明：

- High Quality：映射到 `/printer`。
- Balanced：映射到 `/ebook`。
- Smallest Size：映射到 `/screen`。

官方文档明确说明这些档位会调整输出内容和质量，因此页面不能承诺绝对无损：

- <https://ghostscript.readthedocs.io/en/latest/VectorDevices.html>

### 5.2 Worker 通信

网站内部使用一套固定消息协议：

- 开始任务：任务 ID、文件名、压缩档位和 PDF `ArrayBuffer`。
- 状态事件：Preparing、Compressing、Finalizing。
- 成功事件：输出字节、原始体积、输出体积和处理耗时。
- 失败事件：稳定错误代码和用户可理解的英文错误信息。
- 取消任务：终止当前 Worker，并创建干净的新 Worker 供下次使用。

文件字节必须通过 transferable object 传递，任务结束后清理虚拟文件系统、Worker、Blob 和对象 URL。

## 6. 文件验证与失败处理

必须覆盖以下情况：

- 非 PDF 文件或伪造 `.pdf` 扩展名。
- 空文件。
- 超过 100MB。
- 损坏或无法解析的 PDF。
- 加密、密码保护 PDF。
- 检测到数字签名的 PDF。
- 浏览器内存不足。
- WASM 加载失败。
- 用户取消任务。
- 输出不小于输入。

首版拒绝处理密码保护和检测到数字签名的 PDF。数字签名文件不能在未提示的情况下重写，因为重写通常会使签名失效。

复杂表单、附件、脚本、图层和部分批注不作为首版兼容性保证。隐私页和条款页必须清楚说明这一边界。

## 7. 页面设计与交互

- 视觉以白色或浅灰背景、深海军蓝文字和绿色隐私强调色为主。
- 页面最重要的视觉元素是上传卡和主操作按钮。
- 首屏显示 `Reduce PDF Size Online`、一句价值说明、上传区和本地处理提示。
- 拖放区域同时支持点击、键盘操作和触控。
- 压缩档位要说明质量与体积的取舍。
- 处理状态使用 `aria-live` 对辅助技术播报。
- 所有错误都显示解决建议，不能只显示技术错误代码。
- 移动端不横向滚动，主要按钮达到适合触控的尺寸。
- 除专属社交分享图外，不使用与工具无关的装饰图片。

## 8. SEO 与内容

首页内容按 [seo-content-plan.md](./seo-content-plan.md) 实施。核心要求：

- H1 包含 `Reduce PDF Size`。
- 工具在 SEO 正文之前。
- 自然覆盖 `compress PDF`、`reduce PDF file size`、`make PDF smaller` 等相关表达。
- 重点回答上传限制、保持质量、扫描件和指定体积等真实问题。
- 不复制竞争对手内容，不堆砌同义关键词。
- 不承诺“一定压缩到 300KB/1MB”或“完全不损失质量”。
- FAQPage 结构化数据必须与页面可见问答一致。

## 9. SEO 基础设施

必须提供：

- 唯一且准确的英文 `<title>` 和 meta description。
- canonical URL。
- Open Graph 和 X 分享信息。
- `robots.txt`。
- `sitemap.xml`。
- `WebApplication` JSON-LD。
- 与可见 FAQ 一致的 `FAQPage` JSON-LD。
- 站点 favicon。
- 网站专属社交分享图；文字校验失败时宁可不设置图片，也不能发布错误文字。

生产域名确定后，canonical、站点地图和分享 URL 必须统一使用生产域名，不能残留本地地址、预览地址或旧域名。

## 10. 隐私与安全

- PDF 文件内容不能通过 fetch、XHR、表单、日志、遥测或错误上报发送到服务器。
- 文件名不得作为未转义 HTML 插入页面。
- 压缩引擎必须运行在独立 Worker 中。
- 配置严格 CSP，只允许必要的同源资源，以及 Firebase Analytics 运行所需的明确 Google 域名。
- 不把密钥、令牌或部署凭证提交到源码。
- 不使用第三方文件上传或广告脚本。Firebase Analytics 只能在首屏完成后延迟加载，且应用代码不得向统计事件附加文件名、PDF 字节、压缩档位或压缩结果。
- 页面上的 “Files stay on your device” 必须经过浏览器网络测试验证后才可以发布。

## 11. AGPL 与源码提供

网站应用按 AGPL-3.0 发布，并完成以下工作：

- 根许可证和第三方版权声明。
- 保留 Ghostscript 的版权、许可和必要 Producer 信息。
- `/source` 页面提供与线上版本对应的完整源码获取方式。
- 源码包包含构建说明、依赖锁文件和生成当前版本所需的应用源码。
- 源码包不得包含密钥、部署凭证、缓存、构建产物或用户文件。

Artifex 授权说明：

- <https://artifex.com/licensing>

正式上线前应再次核对当时适用的 Ghostscript 与 Artifex 授权条款。本项目文档不构成法律意见。

## 12. 项目结构与部署

所有网站代码都在 `site/` 中：

```text
reducePdfSize/
├── docs/
└── site/
    ├── app/
    ├── public/
    ├── tests/
    ├── package.json
    └── .openai/
        └── hosting.json
```

后续初始化网站时，必须以 `site/` 作为项目目标目录。开发、安装依赖、构建、测试、打包和部署命令都从 `site/` 执行。

网站完成并通过 [site-completion-checklist.md](./site-completion-checklist.md) 后：

1. 生成生产构建。
2. 确认生产 URL 并更新 canonical 等绝对地址。
3. 再次完成最终构建。
4. 保存经过验证的精确源码版本。
5. 在获得公开发布确认后，从 `site/` 目录部署。
6. 线上分别验证 HTML、静态资源、WASM/Worker 和真实压缩流程。

## 13. 首版不包含

- 批量压缩。
- 登录、账户和云端历史记录。
- 云端压缩兜底。
- 精确压缩到指定 KB/MB。
- 密码输入和加密 PDF 解锁。
- 数字签名 PDF 重写。
- 广告、订阅和支付。
- 用户文件存储。
- PDF 合并、拆分、转换等其他工具。
